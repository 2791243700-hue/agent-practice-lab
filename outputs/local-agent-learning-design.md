## 1. 已确认的需求

- 教学目标是认识 Agent 的用途、理解使用时涉及的概念、调整基本设置并完成实际任务。
- API 是按需讲解的一个概念，不把课程变成 API 开发教程；学生自行申请模型服务的 API Key。
- 使用平台统一提供的教学 Agent，所有实训通过浏览器完成。
- 每一关训练之前提供文字介绍，帮助零经验学生理解本关内容，再进入实际操作；实训过程中可以回看。
- 第一阶段做本地项目。登录、线上部署等功能预留接口，暂不建设账号系统和线上服务。
- 项目按独立轻量应用组织，未把完整 LMS 引入运行依赖。

以下技术选型、首批课程、密钥保存策略和范围取舍作为已采用的本地版基线。实现细节以配套实施计划为准，新增功能不自动纳入首版。

## 2. 本地版的边界与成功标准

首版是运行在学习者自己电脑上的单用户应用：启动本地前后端后，在浏览器学习、配置模型、运行实验、查看记录、提交成果。模型推理使用学生配置的外部服务，因此“本地项目”不等于“离线模型”。

一次完整验收应能够：

1. 在浏览器配置自备模型连接并完成一次真实调用。
2. 打开课程关卡，先阅读文字导读，再按模板创建独立的实验尝试。
3. 修改任务指令，提供课程材料，观察真实工具调用。
4. 批准或拒绝一次产物保存操作；拒绝时不能实际写入。
5. 提交产物，得到可解释的规则检查结果。
6. 刷新页面后找回进度；重新开始实验时获得干净的新工作区，旧记录仍可查看。

首版不包含账号注册、班级与组织管理、云部署、计费系统、多人并发调度、任意终端执行、外部插件市场、实时语音。Skills、MCP、长期记忆等保留为后续课程与能力扩展。

不能出现的结果：只完成聊天界面却没有实验闭环；把模拟响应当作真实调用；用单一标准答案评判所有开放式输出；要求零基础学生先写程序；将不同关卡的文件和状态混在一起。

## 3. 技术方案与选型理由

| 部分 | 本地版建议 | 原因 |
| --- | --- | --- |
| 前端 | Next.js + TypeScript | 统一教学交互；前端仅依赖本项目 API |
| 后端 | FastAPI，单进程运行 | 课程、实验、运行记录、评分统一管理 |
| Agent 内核 | AgentScope SDK，经项目适配层接入 | 利用模型、工具、事件和权限相关能力，教学规则由项目掌握 |
| 结构化数据 | SQLite + SQLAlchemy + Alembic | 免数据库服务，同时保留迁移和更换数据库的基础 |
| 文件 | 项目数据目录下的独立实验工作区 | 初始化、重置和导出简单可控 |
| 实时结果 | HTTP 发起操作，SSE 接收运行事件 | 覆盖文字输出、工具状态、授权请求与完成通知 |
| 运行调度 | 后端进程内任务，首版全局最多一个运行中的任务 | 适合本地单用户；不依赖 Redis 和任务集群 |
| 内容编写 | Markdown 课程说明 + JSON 关卡模板 | 首版通过文件编写课程，暂不制作可视化教师编辑器 |

建议先独立实现轻量应用，LearnHouse 作为课程组织与交互参考，暂不将完整 LMS 作为运行依赖。若后续决定复用 LearnHouse 源码，再单独确定集成边界与所用版本。

AgentScope 的 SDK 与 Agent Service 是不同使用层次。本方案优先嵌入 SDK，不直接部署其完整 Agent Service。该版本包声明将 service、Redis 存储等列为可选依赖，这支持精简依赖的方向；事件、授权与持久化仍需通过最小技术验证确认，不能直接假设完整 Service 的功能自动进入本项目。

实现固定使用 AgentScope v2.0.10，Python 支持 3.11/3.12。依赖已锁定，不追随 main 分支或 dev 文档自动升级；后续升级须重新验证事件和权限适配。

## 4. 模块和可替换接口

以下是本项目设计的接口，名称不代表 AgentScope 原生 API。

| 接口 | 首版本地实现 | 后续可替换实现 |
| --- | --- | --- |
| IdentityProvider | 预留协议与本地实现声明，尚未接入；当前服务/存储固定 local-owner | 登录会话、OAuth、学校统一认证，需贯穿服务、存储和幂等链路 |
| AgentRuntime | AgentScope SDK；运行、取消、授权回复、标准事件输出 | 远程 Agent Service 或其他 harness |
| ModelConnector | 支持工具调用的 OpenAI-compatible Chat Completions 连接适配 | 按提供商增加原生适配器 |
| CredentialStore | API Key 仅存在后端进程内存 | 系统凭据库、加密存储、部署端密钥服务 |
| WorkspaceStore | 创建、读取、保存、快照和导出本地实验文件 | 远程存储或沙箱工作区 |
| ExecutionBackend | 仅课程允许的结构化工具 | 容器或远程沙箱中的执行器 |
| RunDispatcher | 单进程任务与本地运行锁 | 队列任务和远程 worker |
| ProgressRepository | SQLite 保存实验、运行、事件和提交 | PostgreSQL 等数据库 |

业务记录从首版就保留归属字段，不接受浏览器自行声明身份。当前服务和存储默认使用固定的 local-owner，尚未从 IdentityProvider 注入。保留协议声明与归属字段能减少未来改动，但真正线上多用户仍需贯穿身份解析、认证、授权及资源隔离验证。

首版后端绑定回环地址。浏览器通过前端同源 API 转发访问后端；写操作校验来源，后端不对局域网和公网开放。上线不能仅通过更改监听地址完成。

## 5. 首批实训内容

所有关卡复用“课程资料助手”场景，材料是项目自带的虚构课程通知，不涉及真实个人信息。

| 关卡 | 教学目标 | 学生操作与验证 |
| --- | --- | --- |
| 1. 让 Agent 理解任务 | 认识用途、任务目标和约束 | 比较模糊与明确任务指令；真实运行后完成一个简短理解题 |
| 2. 给 Agent 足够的资料 | 理解上下文、附件和信息来源 | 选择课程通知，调用读取工具；输出中应包含来自资料的指定事实 |
| 3. 让 Agent 使用工具 | 理解工具输入、执行结果与继续处理 | 调用预置课程安排查询工具；根据返回信息完成待办草稿 |
| 4. 管理权限并检查成果 | 理解授权、产物与结果核验 | 检查保存请求，练习拒绝与批准；生成待办清单并提交 |

模型连接配置作为入门准备：说明服务商、模型、接口地址与 API Key 的用途，提供连接检查和易懂的错误说明。首版不要求学生编写 HTTP 或 Python 调用代码。

平台默认不给所有高级设置。每个关卡由模板声明可编辑参数和允许的工具；后端同样验证这些限制。修改设置仅影响下一次运行，正在进行的运行使用自己的配置快照。

首版模型适配范围是支持文本与标准工具调用的 OpenAI-compatible Chat Completions 接口，不承诺所有“兼容”提供商均可使用。连接检查分别报告认证/文本调用与工具调用兼容性；课程执行必须通过后者。Provider 原生接口可后续扩展。

### 5.1 每关实训前的文字导读

每关提供必备的、由课程作者编写的 Markdown 导读，按以下顺序组织：

1. **本关学什么**：用一句话说明学完能完成的操作。
2. **先理解这些概念**：每关介绍 1—3 个必要概念，首次出现的术语立即用日常语言解释。
3. **看一个小例子**：用短例子说明概念的作用，帮助学生连接到实际使用。
4. **接下来做什么**：交代本关任务、会提供的材料和需要观察的现象。
5. **做到什么算完成**：用简短条目描述成功标准，与关卡验收规则保持一致。

导读主体建议每关约 200—400 个汉字，配少量任务和完成标准条目；根据内容清楚程度调整，不为凑字数重复概念。文字不要求编程背景，不提前堆积后续关卡的术语，也不直接给出本关实训答案。

进入新关卡或重新开始时先展示该版本导读，学生通过“开始实训”进入操作。导读可在未配置 API Key 时阅读，不触发模型请求或实验工具。进入操作后提供“查看本关介绍”，回看不重置实验；已有实验可直接继续并随时回看。

不设置强制阅读倒计时，不以滚动到底或点击开始作为掌握知识的证明。首版无需额外的阅读时长统计或课前测试；课程完成仍依据实训结果和原有理解题。

四个关卡的具体文字见同目录 [关卡导读草稿](lesson-introductions.md)。内容随 LessonVersion 固定，旧实验回看对应版本；更新导读时发布新版本，不覆盖旧尝试所用内容。

## 6. 实验模板与数据模型

每个模板至少包含：id、version、标题、说明、学习目标、导读文件引用 intro_file、初始文件、允许工具、可编辑设置、默认配置、验收规则、参考事实、资源限制。intro_file 指向课程包内随版本保存的 Markdown 文件；模板校验要求该文件存在且包含导读正文。

| 实体 | 作用 |
| --- | --- |
| ModelProfile | 非敏感模型配置；只关联凭据引用，不保存明文密钥 |
| LessonVersion | 固定版本的关卡定义、文字导读、材料和评分规则 |
| Attempt | 一次实验尝试：owner_id、关卡版本、工作区、当前配置与进度 |
| Run | 一轮 Agent 执行：配置/模型快照、输入、状态、用量和错误 |
| Event | 可重放的消息、工具与授权事件，带 run_id 和递增序号 |
| Approval | 待审批的具体工具调用，绑定参数快照和唯一调用编号 |
| Submission | 提交时的文件与配置快照、规则版本和检查结果 |

每个 Attempt 有独立工作目录。继续学习复用已有 Attempt；“重新开始”创建新 Attempt，复制该关卡的原始材料，不删除旧尝试。

同一 Attempt 的多轮 Run 共享它的实验产物和对话上下文。不同 Attempt 之间不共享运行记忆与文件。个人模型配置可以跨实验复用。

## 7. 运行、授权与恢复

Run 状态：queued、running、awaiting_approval、completed、failed、cancelled、interrupted。这里的 completed 只表示该轮执行完成，不表示通过课程。

- 同一时刻首版全局最多运行一个任务；重复启动返回明确的忙碌状态，浏览器重复点击使用幂等请求标识。
- SSE 事件先持久化，再发送；客户端按事件编号去重并在重连时补读。重新订阅不能再次触发模型调用。
- 浏览器关闭不会立即杀死任务；任务仍受执行超时、轮次和授权等待时限控制。重新打开后读取最新状态。
- 每轮默认最多 10 次模型调用，普通执行最长 120 秒；等待授权单独计时，默认 10 分钟。实际用量存在时保存，缺失时显示“未知”，不编造精确费用。
- 工具执行前检查课时能力范围与授权状态。需要批准的调用必须绑定准确参数；拒绝作为工具结果返回 Agent，不实际执行保存。
- 授权只适用于当前调用。修改参数、重试写入或产生新调用需要新的授权；学生批准不能扩大课程的工具权限。
- 暂停首版指“等待授权”或用户停止当前运行，不实现任意指令位置的进程暂停。
- 停止会取消正在等待的模型请求并阻止后续工具操作；不能保证撤销服务商已接收的调用或费用。
- 进程重启后，将未结束的 Run 标记为 interrupted，过期授权失效；保留已有记录和产物。学生主动开启新一轮运行，不自动重放可能产生副作用的操作。
- 若实验仍在运行，重置需先取消并确认任务结束，然后创建新 Attempt，避免旧任务继续写新实验。

平台记录可见消息、工具名、参数、结果、时间和错误。不要将模型私有推理当作教学必需数据，不承诺展示完整思维链。

## 8. 工具与本地执行范围

首版仅提供受控工具：列出实验材料、读取允许的 UTF-8 文本/Markdown 文件、查询项目内置课程安排数据、保存结构化待办清单。

保存工具接受任务列表数据，由平台生成 todos.md 及对应结构化产物；可让学生检查内容与保存位置，然后批准。工具只能写入当前 Attempt 的产物目录。学生无需理解 JSON 格式才能操作。

文件操作校验规范化路径，拒绝绝对路径、父目录穿越及指向工作区之外的符号链接或 Windows junction；输入大小和工具输出长度均设有限制。初始材料只读，产物写入使用原子替换。

“独立工作区”是本地应用的文件边界，不等于操作系统沙箱。本阶段不开放任意 shell、Python 执行、用户安装的 MCP 服务或自定义可执行插件。将来增加这些能力时，必须先实现 ExecutionBackend 的容器或其他隔离版本。

后续可以增加课程预设 Skills 和 MCP 示例，但需要同时定义工具权限、环境重置和验证方式，不能只增加安装入口。

## 9. 凭据与持久化

默认方案：API Key 在页面输入后送到本地后端，仅存于进程内存；页面可以查看已连接状态但不能读取保存的 Key。模型名、服务商和接口地址可以保存到 SQLite。重启后需要重新输入 Key。

Key 不进入 localStorage、数据库、实验导出、日志或模型提示词。后端异常和第三方错误体经过脱敏处理，避免将请求头或凭据回传给页面。模型调用发生在后端，Key 不注入工具工作区。

首版不实现“记住密钥”；CredentialStore 已为系统凭据库或加密保存预留接口。学生可主动清除当前凭据，正在使用该凭据的任务须先停止。

SQLite 保存进度、事件、提交、模型配置和结果；文件保存在应用数据目录。提交是不可变快照，后续编辑不会改变既有评分。导出只包含学习记录、模板版本和产物，默认不包含个人连接配置。

## 10. 反馈与评测

首版采用可解释的规则评测，不依赖额外的模型裁判调用。分别展示：操作是否完成、事实与产物检查、简短理解题结果。

用户已确认采用“操作过程＋任务结果＋概念理解”的验收方式：

| 关卡 | 必要验收证据 | 开放内容的处理 |
| --- | --- | --- |
| 1 | 同一实验中两次不同任务说明的真实运行，以及简短理解题答对 | 指令表达质量提供建议，不按固定文本打分 |
| 2 | 指定资料成功读取，以及必要事实与来源核对正确 | 自由回答不依赖关键词或固定措辞判定质量 |
| 3 | 指定查询工具按任务参数成功执行，返回信息被正确用于任务 | 用结构化核对项检查日期等事实，不声称自动理解整段自然语言 |
| 4 | 拒绝保存没有写入、批准后确实保存，提交产物包含必要事项与正确日期及来源 | 学生自行检查可读性，平台提供明确的规则证据 |

每次提交绑定本次 Attempt 的操作证据和不可变产物快照。未通过反馈定位缺项，允许修改后重新提交；必要项全部通过才完成关卡。

- 客观操作依据真实运行事件，例如材料读取成功、查询工具返回、拒绝写入未改变文件、批准后成功保存。
- 待办清单依据预置材料检查必要任务、来源标识和日期等结构化字段，不要求固定的中文表达。
- “任务指令是否足够好”等开放目标提供引导和自查项，不伪装成严格自动判断。
- 每条规则给出通过状态、证据引用和改进提示。整个关卡的必要规则全部通过才标记完成；自由表达项目不作硬性失败条件。
- 测试与无 Key 演示使用独立的确定性模拟 Runtime，界面明确显示模拟模式。模拟结果不计为真实实训完成。

## 11. HTTP 扩展边界

以下为接口组的设计概览，已实现字段与新增模型操作以[现行契约](../contracts/README.md)为准。

| 接口组 | 首版实际行为 | 线上扩展点 |
| --- | --- | --- |
| GET /api/v1/me | 返回 local-owner 与 auth_mode=local | 替换身份解析，前端调用方式保留 |
| /api/v1/model-profiles | 非敏感配置、Key 导入、模型列表、多凭据管理及连接检查 | 用户级凭据保存策略 |
| /api/v1/lessons | 读取已发布的本地模板与说明；关卡详情返回对应版本的导读正文 | 教师发布、班级分配 |
| /api/v1/attempts | 创建、读取、重置、读取产物 | 跨设备进度与归属权限 |
| /api/v1/runs | 发起运行、读取状态、停止 | 远程队列与配额 |
| GET /api/v1/runs/{id}/events | SSE 重放和实时事件 | 远程消息与多实例转发 |
| POST /api/v1/approvals/{id}/decision | 接受一次批准/拒绝，防止重复执行 | 统一授权策略 |
| /api/v1/submissions | 创建提交快照、规则评测、读取反馈 | 教师复核与成绩系统 |

登录的“预留”体现为 IdentityProvider 声明、归属字段和 /me 契约；声明尚未接入当前请求链路，不能视为已有可切换身份实现。首版不制作无实际作用的登录页、注册页或空接口。

## 12. 代码和启动组织建议

现有代码目录为 apps/web、apps/api、content/lessons、data、scripts、docs。data 存储 SQLite、实验文件和运行状态，纳入忽略规则；content 保存可版本管理的课程材料。

本机优先支持 Windows。提供一个 PowerShell 启动入口，检查依赖并启动前后端，输出浏览器地址和清晰的失败信息；停止入口清理本项目启动的进程。初版使用源码运行方式，不制作桌面安装包。

前端监听 127.0.0.1:3000，后端建议 127.0.0.1:8000；端口可配置，冲突时提示。用户环境的 Node/Python 版本与包管理器在实现准备阶段检查，不无提示改动全局安装。

## 13. 实现顺序与必要验证

1. **最小技术验证**：AgentScope SDK 真实模型调用、自定义工具、事件转换、批准/拒绝、取消及错误脱敏。记录具体可用的提供商和模型；若 SDK 的授权暂停不能直接复用，由项目工具包装层实现授权等待，保持 AgentRuntime 契约不变。
2. **闭环骨架**：本地身份、SQLite、一个模型配置、一份关卡模板、一条完整运行与提交链路。
3. **教学能力**：四个关卡及实训前导读、配置限制、过程证据、重置、规则反馈与导出。
4. **本地交付**：启动脚本、配置示例、使用说明和真实验证记录。

必要测试覆盖路径边界、归属检查、批准/拒绝的实际副作用、重复请求、取消与重置竞争、重启恢复、事件重放去重、模板版本锁定和评分证据。浏览器验收覆盖模型配置到提交反馈的一条完整路径。

导读的手动验收包括：四关均有实际正文；未配置 Key 也可阅读；开始实训后能回看且不会丢失进度；重新开始和旧实验分别展示正确版本；导读中的完成标准与真实验收规则一致。

使用模拟服务可以完成可重复的自动测试，但不能据此宣称真实模型集成通过；实际 Key 由用户在本地应用中输入，不要求通过聊天提交。没有真实连接验证时必须明确记录该限制。
