# 第一关计划表请求的连接故障处理

日期：2026-10-26。本次作为独立修复提交，合并状态以对应 PR 为准。接口结构、课程归档和评分规则未改变。

## 定位结果

第一关第二轮输入“我有两小时时间，用于完成课程通知任务，请你为我做一份计划表”时，两条历史运行均约 21 秒后失败，错误为 MODEL_UNAVAILABLE，未收到正文。同配置的“看下课程通知”约 1 秒完成。

在用户授权下，使用该关固定通知和第一轮上下文复现了一次 APIConnectionError，随后原计划表请求也多次正常返回。证据支持间歇性的模型连接失败，不能认定是特定措辞或第二轮上下文的确定性错误。原日志隐藏了底层异常，历史两次故障无法进一步还原到具体网络阶段。

## 修复边界

- 实训模型使用单独的 8 秒建连、30 秒读取超时，仍受整轮 120 秒预算限制。
- 仅 OpenAI APIConnectionError 的直接原因明确为 httpx.ConnectError/ConnectTimeout 时等待 0.25 秒后重连一次。这两类错误发生在请求发送前；同一轮不新增已发送的推理请求，model_calls 不因该建连恢复增加。
- 请求读写错误、HTTP 错误和输出开始后的断流均不自动重发；持续建连失败只允许两次连接尝试。取消会终止重连等待。
- 超时、认证和其他连接故障分别使用现有 MODEL_TIMEOUT、MODEL_AUTH_FAILED、MODEL_UNAVAILABLE，并显示可执行的失败提示。
- 诊断只记录运行 ID、异常类型链和 HTTP 状态，不记录 Key、URL、请求、原始响应或异常正文。没有扩大模型目录、连接检查或 Tips 的重试范围。

这项保护可恢复首次建连的短暂故障；持续网络或服务商故障仍会明确失败，不能承诺所有外部请求都成功。

## 验证

后端全量 213 项测试通过，含 12 项传输层回归和 3 项安全错误分类回归；覆盖首次建连恢复、持续失败上限、读取/写入及 HTTP 错误不重发、流式输出中断、取消、工具与凭据边界。

修复启用后，通过网站同源 API 配置用户授权的测试凭据并检查连接，原计划表请求以一次模型调用约 3.4 秒完成，返回 409 字符且包含表格。此前独立进程也验证了原措辞可成功。没有把 Key 或原始模型响应写入此文档；Key 仅保存在本地后端内存，服务重启后仍需重新配置。
