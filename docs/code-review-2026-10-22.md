## P2：实际行为问题

### 1. 第四关未验证“先拒绝、后批准”的顺序

- 代码：[grading.py](../apps/api/src/agent_school/grading.py)，189–218、224–248 行。
- 要求：[第四关任务](../content/lessons/04-permission/task.md)和[接口契约](../contracts/README.md)要求先拒绝，后续批准并保存。
- 实际：两个 evaluator 分别查找任意有效拒绝和任意有效批准，只比较各自调用内的审批/工具顺序，未比较两种操作之间的顺序。
- 影响：先批准生成正确文件，再拒绝一次且保留文件，也能满足全部必需规则，验收与教学步骤不一致。
- 验证：用原 Grader、隔离 SQLite、实际生成/冻结文件及合成事件夹具，按批准在前、拒绝在后输入，两个规则均返回 true。此处是评分单元复核，不是外部模型实测。
- 建议：把拒绝证据与后续成功保存证据关联，跨 Run 使用可靠的全局时间/顺序，不能直接比较不同 Run 的 seq；补反向顺序不通过用例。

### 2. 非法答案提交会留下无主快照

- 代码：[submissions.py](../apps/api/src/agent_school/submissions.py)，20–23 行；[workspaces.py](../apps/api/src/agent_school/workspaces.py)，191–207 行。
- 触发：向第三关提交 ChoiceAnswers 等“符合 Answers 联合 schema，但不属于本关”的结构。
- 实际：先 freeze 文件，后执行 Grader.validate_answers；后者返回 422 时，数据库事务回滚不会清理文件系统。
- 影响：失败提交也复制材料/产物；重复尝试持续增加没有 Submission 引用的快照目录。
- 验证：真实 School/SubmissionService 在独立临时目录、数据库事务内连续提交两次非法答案，新增 2 个快照目录，Submission 记录仍为 0。测试后隔离目录已清理。
- 建议：关卡答案校验前移到冻结之前；冻结后的任意失败另需可靠清理或分阶段发布。现有 test_grading.py 已断言该错误返回 422，但未检查文件残留。

### 3. 历史实验的“预览原文”被一并禁用

- 代码：[practice 页面](../apps/web/src/app/practice/[id]/page.tsx)，319、339–346 行。
- 触发：重新开始后，从学习记录回看旧实验。
- 实际：材料选择和预览按钮都位于 `disabled={historical || action.busy}` 的 fieldset 内。历史状态使原文预览按钮失效。
- 影响：文档承诺旧实验可读，但学生无法从该页面的材料入口核对原文。产物预览位于另一块，不能替代材料入口。
- 建议：仅禁用修改设置的控件，将只读预览移出禁用范围；补历史实验材料预览用例。此项由 DOM 结构及 HTML fieldset 禁用语义确认，本轮未运行浏览器复现。

### 4. 手动模型重输 Key 成功，却显示目录错误

- 代码：[key-manager.tsx](../apps/web/src/components/key-manager.tsx)，74–78、547–552 行。
- 触发：使用明确不支持 GET /models 的兼容接口，手动配置模型；重新进入设置页或重启后重新输入 Key。
- 实际：凭据 PUT 成功并刷新配置后，无条件 fetchModels；预期的 MODEL_CATALOG_UNSUPPORTED 被当成整个操作失败，成功提示无法执行。
- 影响：Key 实际已保存到内存，页面却报错，容易让新手重复提交。并非凭据丢失，也不能据此断言后续检查无法继续。
- 建议：将凭据提交与目录刷新结果分开，对手动模式保留已有模型并给非阻断说明；覆盖刷新、重新选择和重输三种入口。

### 5. 契约允许的版本名可能使整个课程列表失败

- 代码：[lessons.py](../apps/api/src/agent_school/lessons.py)，66–69 行；[lesson.schema.json](../contracts/lesson.schema.json)，15–18 行。
- 触发：同一课程同时存在 `1.0.0` 与 `1.0.beta`，二者都符合当前 version 字段约束。
- 实际：排序键把数字段转为 int，其余保留 str，max 比较到混合段时抛 TypeError；listLessons 逐课取最新版，因此可导致整个列表返回 500。
- 验证：隔离课程库加载两个 schema 合法版本，调用原 LessonCatalog.get，确认 TypeError。当前自带四关均为 1.0.0，不触发该问题；新版本发布会遇到风险。
- 建议：明确支持的版本格式，同步 schema 与排序器；增加合法预发布版本或非法格式拒绝用例。

### 6. 发布时未拒绝“没有必需规则”的课程

- 代码：[lessons.py](../apps/api/src/agent_school/lessons.py)，34–38、51–57 行；[submissions.py](../apps/api/src/agent_school/submissions.py)，24–26 行。
- 要求：契约明确“没有必需规则或规则配置无效的课件禁止发布”。
- 实际：只检查 rules 非空；所有 required=false 的课程仍符合 schema 并可发布，提交时却因 bool(required)=false 永远不能通过。
- 验证：真实契约校验接受全部可选规则，原 publish/get 接受该课程。当前自带课程均有必需规则，问题出现在新增/改版课件时。
- 建议：导入/发布统一校验至少一条 required=true，同时核对答案表单与 evaluator 的匹配，防止无效组合延迟到评分才失败。
