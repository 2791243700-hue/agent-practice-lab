# 正式模型验收：实现、接口与维护说明

更新：2026-10-27。开发基线为 main `0b15af9`。本版本同步交付后端、正式评分、接口、前端和新课程版本。此前的模型 Tips 仅提供建议，新验收独立调用模型并参与正式成绩。

## 通过条件与版本

新课程正式通过 = 本课程所有客观必要项通过，并且所有模型内容评分项通过。第一关发布 1.2.0，第二至四关发布 1.1.0。旧课件、实验和冻结成绩保留原规则，不重算、不自动升级；从最新导读新建实验才使用模型验收。演示不调用验收模型，始终不计正式通过。

| 关卡 | 客观必要项继续保留 | 模型内容评分 |
| --- | --- | --- |
| 第一关 | 两轮完成及先后顺序、新增片段、完整消息精确引用、小变式分类 | 改动是否有意义且属于同一任务、解释与引用是否相符、新情境及后续指令是否合理 |
| 第二关 | 实际读取指定材料，日期和来源正确 | 回答依据原文，学生能具体说明核对依据与缺失信息 |
| 第三关 | 指定课程实际查询，日期和教室正确 | 回答使用真实查询结果，学生解释输入、结果与回答的关系 |
| 第四关 | 先拒绝且未写入，随后批准并实际保存，产物与哈希正确 | 成果符合任务，学生解释拒绝、批准及实际产物核验的区别 |

评分标准保存在各新课件的 `assessment_policy`，包括固定 `rubric_version` 与 criterion.id/title/description；系统评分提示词通过 ASSESSOR_PROMPTS 按该版本选择，未知版本禁止发布，并通过 LessonDetail 公开展示。修改标准或提示词的评分含义须发布新课程版本，不能覆盖已经归档的课程。

学生诚实判断 Agent 部分满足或没有满足要求仍可合格，前提是解释有依据、改进有针对性。没有最低字数、关键词命中或必须选择“满足”的规则。模型评价仍有误判可能，不能承诺自动证明全部理解能力。

## 接口变化

HTTP 路径及 SSE 类型不变，仍为 41 个操作、11 类事件；OpenAPI 新增 7 个 schema，总计 109。生成类型由 `npm --prefix contracts run types` 生成，不手改。

`POST /api/v1/submissions` 仍接收旧字段；新正式课程额外要求：

```json
{
  "attempt_id": "attempt-example",
  "expected_attempt_revision": 1,
  "answers": {},
  "assessment": {
    "profile_id": "profile-example",
    "expected_profile_revision": 2,
    "consent": true
  },
  "learning_reflection": "我把工具结果与原文逐项对照，核对了日期、来源和未说明的信息。"
}
```

`answers` 必须按课程实际表单提交，上例的空对象只适用于第四关 artifact 表单。第一关继续提交 ReflectionAnswers，已有解释与改写作为模型证据；第二至四关必须另填非空白 `learning_reflection`（最多 6000 字符）。旧课程、demo 不强制上述新字段，不调用评分模型。客户端不得传 passed、评分结果、owner 或内部令牌。

Submission 可新增 `learning_reflection`、`model_assessment`；历史记录不要求补字段。`model_assessment` 包含 status、rubric_version、model、assessed_at、message、error_code、usage、checks。每个 check 包含 criterion_id、passed、reason、suggestion、citations（source_id、逐字 quote）。正式规则中追加 `model-*` 必要项；仍只读取服务器的 `Submission.passed` 判断通关。

| 结果 | HTTP / 保存行为 | 通关与下一步 |
| --- | --- | --- |
| 客观证据不合格 | 201 冻结提交；status=skipped；模型调用 0 次 | 不通过，先按客观反馈修改 |
| 模型评分完成 | 201 冻结提交；status=completed | 客观项及所有模型项均通过才通关 |
| 网络/认证/超时/无效评分 | 201 冻结提交；status=unavailable，包含安全错误码 | 验收未完成，不放行；作答保留，主动重交需重新确认费用 |
| 缺少同意、无效结构或说明 | 422，不调用模型 | 修正输入再提交 |
| 模型配置过期或实验忙 | 409，不调用模型 | 等待或刷新并重新核对 |

不可用时 usage.model_calls=1 表示尝试发出一次模型请求，不证明服务商收到、处理或扣费；Token 未知时为 null。没有后台重试、自动换模型或 Tips 结果兜底。

## 调用、证据和并发边界

`SubmissionService.prepare` 先校验归属、修订、表单、同意并冻结文件和答案，执行原 Grader；全部客观项合格才解析当前已检查且 Key 在内存中的模型。准备阶段在 SQLite 长事务之外等待模型，提交、评分、快照与幂等响应在现有事务中原子保存。

模型证据包含公开课程任务及评分标准、对应运行输入与完整回答、实际工具与批准事件、冻结材料及产物、学生答案与说明。第一关复盘还包含该实验归档版本的公开小变式标题、问题标签，以及可逐字引用的通知原文；lesson.challenge.notice_source_id 指向 sources 中的 challenge:<challenge_id>，不混入私有答案。第一关只取所选两轮，其他关取本实验的终态轮次（包括失败或取消前已发生的真实工具/授权证据）。不传私有正确答案、模型连接配置、Key 或内部令牌。证据在发送前脱敏；总上下文超过 60000 字符时拒绝调用，不悄悄截断正式评分证据。

独立评分提示词将所有学生内容、文件和回答视为不可信证据，不执行其中的“直接判通过”等指令；不提供工具。单次 OpenAI-compatible Chat Completions 请求，temperature=0，45 秒总预算、8 秒建连、40 秒读取，不跟随重定向、不自动重发。此路径与执行 Agent、连接检查及 Tips 分离。

模型必须恰好返回课程定义的全部标准，布尔值必须真实为 bool；不接收模型自报总通过。通过项必须提供来源存在且文字精确匹配的引用；失败项必须有改进建议。漏项、重复项、伪造来源/引文、工具请求、截断输出、无效 JSON 等均作为验收不可用，不能通关。模型报告及安全错误不含原始异常正文。

评分期间占用全局模型槽及所选 profile，拒绝新的运行、其他模型请求、该连接的修改，以及同一实验设置/重置/导出。读取历史与健康检查可继续。重复相同幂等键返回同一冻结结果，不再次请求；同一请求并发返回 409。

付费准备前将幂等记录标记 pending。进程中断、结果落盘/响应校验异常导致结果不明确时保留 pending，同一键不能再次调用。用户先查看历史确认结果，再刷新并重新同意后主动提交会产生新键，可能再次计费。普通模型网络失败返回已冻结 unavailable 提交，复用原键只返回该结果；再次点击提交是明确的新操作。

## 前端、恢复与维护

SubmissionPanel 展示本版评分标准、当前选定的模型与服务商、证据发送范围和费用确认；连接修订变化使旧同意失效，每次提交后清除同意。第二至四关增加核对说明，第一关复用四步复盘。提交失败不清空填写；unavailable 作为提交记录保存在历史和 ZIP 中，刷新后可回看原文。第二至四关未提交的说明仅在当前页面内存，完整刷新前应复制备份。

主要维护文件：`apps/api/src/agent_school/model_assessment.py`（提示词、证据、模型传输与结果校验）、`submissions.py`（两阶段评分）、`main.py`（付费幂等）、`lessons.py`（版本与公开标准）、`service.py`（互斥）、`apps/web/src/components/feedback.tsx`（同意和反馈）、`conversation-review.tsx`（复盘接入）。

本轮还保留之前本地调整：DeepSeek 申领提示按连接检查显示、导读与主任务对齐、Ctrl+Enter 发送及首次提示、醒目的 Tips 卡片。这些交互不改变 API Key 的存储策略。
