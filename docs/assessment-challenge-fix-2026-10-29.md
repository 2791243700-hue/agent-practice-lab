# 小变式通知评分证据修复

日期：2026-10-29。基线为 main `3aebaa7`（PR #15）；该修复随第一关 1.3.0 精简验收一并交付。

第一关 1.2.0 要求验收模型判断迁移指令是否符合活动通知，但此前内部评分上下文没有发送 `answer_form.challenge.notice`。冻结文件只有课程总结和实验室预约通知，无法替代小变式的活动通知，可能导致模型误判。

`ModelAssessor.context()` 现从实验固定课程版本的归档表单取公开小变式。`lesson.challenge` 提供 id、title、items（仅 id/label）和 notice_source_id；通知原文单独放在 `sources["challenge:<challenge_id>"]`，经统一脱敏、上下文大小检查与既有逐字引用校验。发布更新的课程版本后，旧实验仍使用其固定版本的原文，不能引用其他版本通知冒充证据。

私有 `rules`、`expected_judgments` 和其他评分参数不随小变式发送。其他三关不新增小变式字段；旧课程和已冻结的提交仍按原规则处理。本次不改课程包、评分标准或提示词版本，仅补齐公开证据；HTTP/SSE 契约及生成类型不变，该项修复单独不改变原 41 个操作、109 个 schema、11 类事件；合并精简验收后的总数见当前版本索引。

## 验证

新增三个正式提交流程回归：当前通知可被模型真实引用；发布较新版本后仍发送固定旧版本；引用较新版本的原文会被拒绝。三个用例在修复前均因缺少原文失败，修复后通过；同时核对费用幂等、私有答案及凭据不外发。第二至四关的既有真实工具流程也检查不混入小变式。

模型验收专项 32 项、后端全量 245 项、契约结构 244 项通过；Ruff、56 个 Python 文件格式和差异检查通过。36 份文档及本地链接、HTTP 操作清单核对通过。本次没有前端改动，未重跑前端构建或浏览器全量。测试仅使用本地 MockTransport 和虚构凭据，未调用真实外部模型、使用私人 Key 或改动学习数据。
