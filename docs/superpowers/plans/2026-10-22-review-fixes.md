# 审查问题修复计划

**Goal:** 修复整体审查报告中的行为偏差，清理确认无用的代码，并使文档准确描述实现与验证。

**Architecture:** 沿用本地单用户、JSON 契约、不可变提交和内存凭据。后端修复验收/快照/课件校验；前端修复历史只读预览与兼容模型凭据恢复；保留仍有用途的兼容接口和类型适配。

**Spec:** [审查报告](../../code-review-2026-10-22.md)。用户已要求按报告修改，直接执行。

## 约束与决策

- 保留当前工作区全部已有改动，不读取用户 Key、日常 data 或使用外部模型。自动化使用隔离目录和脚本提供商。
- 第四关必须有有效拒绝在先、匹配当前产物的成功批准保存在后，跨 Run 不能只比较局部 seq；旧提交快照不重算。
- 提交前先校验关卡答案；冻结失败或评分失败时清理该次未发布快照，不清理其他历史。
- 保持课程版本字符串现有兼容范围，采用确定且可比较的排序键，明确数值正式版本与文本版本的顺序。
- 课件发布统一验证必需规则及表单/evaluator 匹配，未修改现有课程内容。
- IdentityProvider 保留为扩展声明，文档准确标注尚未接入，避免本次扩展为登录重构。

## 任务

- [x] 后端：先加顺序反例、非法提交无残留、冻结失败清理、版本混合及全可选规则/错误表单测试，确认失败，再修复并跑后端完整测试。
- [x] 前端：先补历史材料预览及手动模型重启重输/检查回归，确认失败，再修复；清理旧 CSS、未使用绑定和重复刷新。
- [x] 维护：移除空 signals 通知路径，修正指纹缓存注释、身份扩展和测试覆盖文档；审查报告增加逐项关闭记录。
- [x] 验证：契约、Ruff、前端严格未使用检查、单元测试、隔离生产构建与完整浏览器流程；独立复审修复差异，记录准确结果。

## 重点边界

拒绝/批准跨运行且时间相近；批准在前的反例不能通过；快照只清理本次；重输成功与目录失败分开；目录刷新不重复付费检查；已发布课件与旧成绩保持可读。

91 项后端、8 项前端、15 项浏览器及 197 项契约检查通过；Ruff、格式、严格类型及隔离生产构建通过。独立复审补充的事务回滚与材料引用问题已补测关闭。上述为该轮历史验证结果；改动已通过 PR #6 合并到 main，后续前端体验增量随 PR #7 合并，PR #7 的浏览器总数为 26；当前复盘预览的 30 项结果见前端验证报告。
