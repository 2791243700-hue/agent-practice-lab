## 发现并修复的问题

1. 官方 DeepSeek 默认 thinking 与强制工具选择冲突。连接检查及运行共用 provider options，仅对官方主机关闭 thinking，修复后实际工具调用通过。
2. AgentScope 2.0.10 外部工具权限回调要求 message 参数；补齐参数，保留项目网关的逐次保存授权，并明确写工具需要审批。

两项修复已随 [PR #4](https://github.com/2791243700-hue/agent-practice-lab/pull/4) 合并，回归见[后端验证](runtime-validation.md)。服务商行为依据当时实测；相关接口说明见[DeepSeek 模型列表](https://api-docs.deepseek.com/api/list-models/)和[thinking 模式](https://api-docs.deepseek.com/guides/thinking_mode/)。

## 不能由本次结果推出的结论

- 第四关的公开材料/任务尚未充分解释必要任务 ID。实测显式补充映射后通过，不代表零经验学生能独立完成；需发布新课程版本并重新验收。
- 后端成功不等于已完成人工浏览器验收，也不代表所有 DeepSeek 模型或 OpenAI/其他兼容服务都能运行。
- 2026-10-22 新增的 Key 导入、模型目录和多 Key 管理只通过 MockTransport/本地脚本模型测试，没有用真实私人 Key 复测；此前直接获取列表不等于新产品入口已实测。
- 模型目录成功只说明列出服务商返回的模型；所选模型仍需主动通过文本及工具兼容检查。演示与脚本服务不能替代外部验证。
